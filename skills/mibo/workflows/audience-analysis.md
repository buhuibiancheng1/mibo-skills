# 查看粉丝画像与受众分析

“查看粉丝画像”“分析粉丝”“受众分析”使用 13「粉丝与受众分析」（`skill-audience-profiler`）。通过 `mibo_run_skill` 提交，已有项目才填写 `project_id`，否则保存账号级任务，不创建画像。账号主页使用 `input.url`，多账号使用 `input.data.accounts`（`platform`、`url`）；已有后台统计、评论或文字资料放入 `data.statistics`、`data.comments`、`data.text`，无须为了分析已有资料再次采集。

后台先复用同项目的账号来源、评论与粉丝统计。只有用户明确要求刷新统计时，才使用 `options.refresh=true`；普通查询、续改、13 与 11 衔接不重新提交同一份统计。需要指定范围时，`options.dimensions` 仅选择 `gender`、`age`、`province`、`city`、`city_tier`、`interests`、`device_price`、`device_brand`。缺少统计的平台保留已有评论分析范围，不扩大到未经验证的数据渠道。

沿用原请求编号查询 `mibo_get_task(kind=workflow)`。准备期间只给文字进度，不逐维度打开卡片。`delivery.next_action=analyze_audience` 后，读取 `state.audience` 与 `audience-evidence.json`，继续完成报告。资料已准备不等于报告已完成；用 `mibo_complete_skill` 保存完整正文，然后在当前对话完整交付。后续续改使用保存的报告及证据，不重新采集。

报告包含三个清楚区分的部分：

1. **已取得的粉丝统计。** 仅展示实际返回的维度，保留账号、记录编号、采集时间、已提供的统计周期与基数；缺少周期或基数时说明缺项；返回的分布不默认称官方后台统计或已经核验的全体粉丝。百分比、比例、数量分开；`unit=unspecified` 的数值不得自行换算百分比。缺失不补零，实际零保留；部分维度、截取的类别不能冒充完整人口结构。
2. **评论样本中的问题、需求和异议。** 写明实际作品与去重评论数、采集时间，并保留原句、作品链接及评论编号。评论者不等于粉丝，不据昵称、头像或少量评论推断全体粉丝年龄、收入或购买能力。手机价格、品牌不等于收入、消费能力或购买意向。用户提供的资料标清来源，不当作后台自动核验的统计。
3. **新的内容机会。** 每个方向说明依据、新的观众问题、与采样作品题材的实质区别、首条内容与试拍条件。旧作品诊断与新方向分开，不把续写、复测、答疑或换对象包装成全新方向。

11「分析参考账号」已内含同一份受众证据，不另开 13 重复采集。11 还须实际读取原片声音和画面，保留作品与时间证据，完成完整账号报告；粉丝统计不能替代声画分析。

涉及平台选择时，统一遵循[平台识别与选择](../references/platform-selection.md)：已有链接或明确平台不重问，两者均不能确定时先提问并等待回答，再执行。
